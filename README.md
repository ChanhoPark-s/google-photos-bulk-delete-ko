# Google Photos 날짜별 일괄 삭제 (한국어) 📷

**Google Photos Date-Group Bulk Delete Helper (Korean/English)**

> **반복 작업에 쓰는 시간은 줄이고, 더 중요한 일에 시간을 쓸 수 있었으면 좋겠습니다.**
>
> 모든 사람이 조금 더 편하고 효율적으로 살아가길 바라는 마음으로 만들었습니다. 이미 공유되어 온 Google 포토 자동 삭제 아이디어를 참고하되, 단순 반복 클릭 방식의 불편함을 줄이려고 **날짜별 한 번에 선택하기, 불필요한 고정 대기 줄이기, 처리 단계 확인, 안전 중단**을 중심으로 새로 정리한 실험적 도구입니다.

**⚠️ 주의: 이 스크립트는 실제 사진과 동영상을 휴지통으로 이동합니다.** 실행 전에 코드를 직접 확인하고, 필요한 사진을 별도로 백업하세요. Google 포토 백업·동기화가 켜진 다른 기기에서도 삭제될 수 있습니다.

**상태: v1.2 · 실험적(Experimental).** 한국어 Google 포토 화면에서 날짜 체크박스가 탐지되고 날짜 2개가 선택되는 모습은 확인했지만, **이 저장소에 게시된 최종 버전의 삭제 확인창 처리 및 전체 라이브러리 삭제를 실제 계정에서 끝까지 검증한 상태는 아닙니다.** Google 포토의 UI 변경에 따라 작동하지 않을 수 있습니다. Google의 공식 도구가 아닙니다.

## v1.2 변경 내용 (2026-11-01)

- 기본 날짜 묶음 최대 **10일**로 확대(화면에 실제로 로드된 날짜 범위 내에서만 적용).
- 날짜 체크 후 상태 확인이 안 되면 다음 날짜를 계속 클릭하지 않도록 개선.
- 삭제 반영 검증의 **날짜 제목 완전 제거 필수 조건**을 수정. 사진 목록 변화 또는 완료 알림도 고려.
- 최대 90초 동안 처리 상태를 확인하며 대기 로그 출력(백그라운드 탭 대기는 시간 제한에서 제외).
- 영구 삭제 버튼과 일반적인 보관 기간 안내 문구를 구분.
- 선택 수가 확인되는 경우 기본 **500장 안전 상한** 적용. Google의 공식 제한 수치가 아님.
- **최종 버전의 실제 계정 전체 삭제 테스트는 아직 완료되지 않았음.**

## v1.2 변경 사항

날짜 체크박스를 찾을 때 화면 좌표 조건을 제거했습니다. 날짜 헤더가 0개로 잡히면 로딩을 기다린 뒤 진단 정보를 출력합니다. 날짜별 체크박스만 클릭하고 사진을 개별 클릭하지 않습니다. 현재 DOM에 없는 날짜는 스크롤 없이 선택할 수 없습니다.

| 기존의 단순 클릭 반복 방식 | 이 프로젝트의 접근 |
| --- | --- |
| 화면의 사진을 한 장씩 클릭 | **날짜 전체 선택** 체크박스를 클릭 |
| 매번 고정된 긴 주기로 반복 | 다음 버튼·화면 변화를 **짧은 간격으로 감지** |
| 삭제 성공 확인 없이 다음 반복 | **확인창 처리 → 선택 해제·사진 목록 변경 또는 완료 알림 확인** 순으로 진행 |
| UI가 달라지면 엉뚱한 버튼을 누를 위험 | 확인 버튼을 식별하지 못하면 **사용자가 직접 누르도록 안내** |
| 작업 중단 방법이 불명확 | 콘솔에서 **중단·상태 조회 명령** 지원 |

사진이나 동영상의 정확한 삭제 개수를 계산하는 프로그램은 아닙니다. 완료 로그는 Google 서버의 최종 삭제를 보증하지 않고, **현재 웹 화면에서 처리 단계가 끝난 것으로 판단했다는 의미**입니다.

## 사용 방법 (Windows / Chrome 기준)

1. **사진 백업**과 **동기화 영향을 반드시 확인**하세요. Google 공식 삭제 안내: https://support.google.com/photos/answer/6128858
2. PC 브라우저에서 [Google 포토](https://photos.google.com/)에 접속한 뒤 **사진 목록**을 엽니다. 휴지통·앨범·개별 사진 상세 화면에서는 실행하지 마세요.
3. 기존에 실행하던 다른 삭제 스크립트가 있다면 **F5**로 새로고침해 종료합니다. 이미 선택된 사진이 없어야 합니다.
4. 이 저장소의 **[delete-photos.js](./delete-photos.js)** 파일을 열고 **Raw**를 눌러 전체 코드를 확인한 후 복사합니다.
5. Google 포토 탭에서 **F12 → Console(콘솔)**을 엽니다. 복사한 코드를 붙여넣고 Enter를 누릅니다.
6. 첫 확인창에서 실제 삭제에 동의하면 화면에 표시된 날짜들을 선택하고 휴지통 이동을 시작합니다.
7. **버튼을 자동으로 인식하지 못했다는 메시지가 나타나면**, 화면에 뜬 Google 포토의 삭제 확인창을 직접 확인하세요. 스크립트는 해당 단계를 대기합니다.
8. 콘솔에 **"✅ 삭제 주기 검증 완료 (웹 화면 기준)"**가 나타난 뒤에만 다음 날짜 묶음을 처리합니다.
9. 작업이 종료되면 **페이지를 새로고침하여 남은 사진과 휴지통을 직접 확인**하세요.

**설치, 로그인 정보 입력, 외부 서버 연결은 필요하지 않습니다.** 코드는 현재 열려 있는 Google 포토 웹페이지의 버튼을 조작합니다. 스크립트에 분석용 전송 코드나 외부 API 요청은 없습니다.

### 실행 중 중단

콘솔에 아래 명령을 입력하세요.

~~~javascript
window.GPDateDeleteKO.stop()
~~~

상태 확인:

~~~javascript
window.GPDateDeleteKO.status()
~~~

중단은 **다음 동작을 막는 요청**입니다. 이미 휴지통으로 이동한 항목을 되돌리지는 못하며, 현재 열려 있는 확인창이나 선택 상태는 직접 확인해야 합니다. 브라우저에서 F5를 눌러도 자동화 실행은 종료됩니다.

## 속도 및 날짜 개수 설정

[delete-photos.js](./delete-photos.js) 파일 위쪽에서 아래 숫자를 바꿀 수 있습니다.

~~~javascript
maxDatesPerBatch: 10, // 날짜 최대 10개
pollMs: 180,
loadWaitMs: 12000,
settleWaitMs: 45000,
nextBatchMs: 650
~~~

**중요:** 최대 날짜 개수를 10으로 설정해도 현재 화면에서 날짜 버튼이 2개만 로드됐으면 **2개만 선택**됩니다. 이 스크립트는 **자동 스크롤을 하지 않습니다**. 삭제 후 새 날짜가 자동으로 나타나지 않는다면 해당 위치에서 종료하며, 이는 Google 포토의 모든 사진이 없어졌다는 뜻이 아닙니다. 필요하면 사용자가 화면을 이동한 뒤 새로고침하고 다시 실행해야 합니다.

많은 날짜를 무조건 동시에 선택하는 것보다 화면이 안정적으로 반응하는 범위에서 묶는 것이 안전합니다.

## 문제 해결

**Q. 2일씩만 선택돼요.**  
A. 날짜 묶음 상한보다 **현재 로드된 날짜 헤더 개수**가 작기 때문입니다. 다음 명령으로 개수를 확인할 수 있습니다.

~~~javascript
document.querySelectorAll('[role="checkbox"].R4HkWb').length
~~~

**Q. 삭제 확인창에서 멈췄어요.**  
A. Google 포토의 UI나 표시 언어에 따라 버튼 문구가 다를 수 있습니다. 콘솔에 출력된 버튼 목록과 실제 확인창을 점검하세요. 자동 인식에 실패하면 확인 버튼을 **직접 클릭**하도록 안내하며, 일정 시간이 지나면 중단합니다. 확인하지 않은 버튼을 추측해서 클릭하지 않습니다.

**Q. 날짜는 선택됐는데 삭제 검증에서 멈춰요.**  
A. v1.2은 날짜 제목이 사라지는 것만 요구하던 과도한 검증을 수정했습니다. 이제 **선택 상태 해제 + 삭제 도구 모음 종료 + 날짜/사진 목록 변화 또는 새 삭제 완료 알림**을 확인합니다. 그래도 90초 내 검증되지 않으면 **삭제 성공 여부를 단정하지 않고 중단**합니다. 현재 화면과 휴지통을 직접 확인하고, 필요하면 F5 후 다시 시도하세요.

**Q. 날짜를 클릭하는 것처럼 보이는데 선택은 안 돼요.**  
A. 화면 갱신 중이거나 체크박스 구조가 바뀌었을 수 있습니다. 클릭 후 **최대 6초간 선택 상태를 검증**하며, 실패한 날짜를 무작정 다시 클릭하지 않습니다(재클릭하면 오히려 선택이 해제될 수 있기 때문). Google 포토 탭을 전면에 두고, 선택 모드가 남았다면 F5 후 다시 시도하세요.

**Q. 최대 10일인데 왜 2일만 선택하나요?**  
A. `maxDatesPerBatch: 10`은 **상한**입니다. 개발자 도구를 화면 아래에 붙이면 사진 영역이 작아져 현재 표시되는 날짜가 줄어들 수 있습니다. DevTools를 별도 창으로 분리해 사진 표시 영역을 넓히면 더 많은 날짜가 로드될 수 있지만, 이 스크립트가 자동으로 스크롤하지는 않습니다.

**Q. 500장 제한에 도달했어요.**  
A. 공개 버전은 선택 수를 읽을 수 있을 때 **500장 이상이 되면 더 많은 날짜 선택을 멈추고, 500장을 초과하면 삭제하지 않고 중단**합니다. 이는 Google의 공식 한도가 아니라 큰 묶음에서 발생하는 UI 지연을 줄이려는 보수적 설정입니다. 상황에 따라 상한을 조절할 수 있지만, 많이 선택했다고 항상 빠르거나 안정적인 것은 아닙니다.

**Q. 더 이상 날짜가 없다고 하는데 사진이 남아 있어요.**  
A. 스크롤 없이 현재 보이는 날짜만 처리하기 때문입니다. 화면을 이동해 날짜가 새로 로드되면 다시 실행할 수 있습니다.

**Q. 사진을 다시 되찾을 수 있나요?**  
A. 아직 휴지통에 남아 있는 항목은 Google 포토에서 복원 가능한 경우가 있습니다. 현재 보관 기간과 복원 조건은 [Google 공식 도움말](https://support.google.com/photos/answer/6128858)에서 확인하세요. **휴지통을 비워 영구 삭제하면 복구할 수 없습니다.**

## 개인정보와 안전

- **비밀번호, Google 로그인 토큰, 사진 파일을 수집하거나 전송하는 코드는 없습니다.**
- 단, 브라우저 콘솔에서 실행하는 모든 코드는 로그인한 페이지를 조작할 수 있습니다. **소스를 읽어 보고 신뢰할 수 있을 때만 실행**하세요.
- Google 계정·기기의 백업/동기화 설정에 따라 다른 기기의 사진에도 영향을 줄 수 있습니다.
- 사진과 동영상을 **휴지통으로 이동**하는 스크립트이지, 휴지통을 자동으로 비우는 도구가 아닙니다.
- 보관처리된 사진, 특수 앨범, 잠긴 폴더 등 모든 별도 영역의 항목을 찾아내는 도구가 아닙니다.
